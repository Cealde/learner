2. Backend & Data Pipeline (Rust)

2.1 Why Rust and Tauri v2?

  • Tiny Binary: Compiles to 10-15MB versus Electron 150MB+ by utilizing the OS native webview.
  • Memory Safety: Zero data-races during asynchronous child process execution.
  • Instant Launch: Near-zero cold start overhead compared to heavy Node.js runtimes.

2.2 Profile & Mistake Ledger Processing

User progression data is managed through structured state:

  • Progress Struct: Tracks active specialization, current lesson milestone, subtopic pointer, and completed subtopics array.
  • Mistake Ledger: Records incorrect quiz and code submission attempts keyed by lesson ID. When mistake threshold is met, remediation flow triggers automatically.
  • Mastery Reset: Upon successful 100% completion of a lesson, clear_lesson_mistakes flushes the error count to reward user mastery.

2.3 Execution Safety & Sandboxing

Python code is executed via child processes with enforced process timeouts (3000ms), capturing stdout and stderr streams safely and preventing runaway infinite loops from freezing the desktop app.

3. Journey Map (Three.js 2.5D)

3.1 Mathematical Projection

The journey map employs a custom 2.5D orthographic camera view to deliver a stylized blueprint feel without perspective distortion:

Frustum_W = frustumSize * aspectRatio
Frustum_H = frustumSize
Pitch(zoom) = Pitch_min + (Pitch_max - Pitch_min) * ZoomFactor

3.2 Dynamic Visual States

  • Completed Milestones: Solid emerald green mesh with permanent connecting ribbon.
  • Active Milestone: Pulsing cyan highlight ring oscillating at 1.0 + 0.16 * sin(3.0t), accompanied by a dynamic upward swirl particle vortex.
  • Locked Milestones: Desaturated dark nodes with dashed trajectory paths.

3.3 Performance Optimizations

  • Infinite ground tracking updates UV texture offsets instead of generating new terrain geometry.
  • Low draw-call count (< 25 calls per frame) maintains a rock-solid 60 FPS on low-power laptops.

4. Multi-Stage Lesson Engine

4.1 Interactive Multi-Stage Stepper

To avoid overwhelming novice programmers, coding challenges are broken into progressive micro-stages (e.g. Stage 1: Declare Variable → Stage 2: Perform Operation → Stage 3: Output Result).

  • Code Cache Isolation: stageCodeCache saves student code per stage, allowing seamless forward/backward navigation between unlocked stages without loss of written code.
  • Validation Gatekeeper: Next stage unlocks only when current stage outputs match the exact test matrix.

4.2 Cognitive Scaffolding & Content Rigor

  • Strict Pedagogy Order: Variables are taught thoroughly before arithmetic and string concatenation to eliminate cognitive overload.
  • Real-World Analogies: Explains memory assignment via labeled storage containers, conditionals via airport security checks, and loops via factory conveyor belts.
  • Zero Pictorial Emojis: High-density, professional UI adhering strictly to clean UI standards.

5. Offline AI & Adaptive Tutoring

5.1 Deterministic AST Diagnostic Engine

When running 100% offline, the tutor parses Python code into an Abstract Syntax Tree (AST) to detect exact structural errors before runtime:

  • Missing colons after if, for, or def statements.
  • Indentation inconsistencies and block boundary errors.
  • Undefined variable references and assignment vs equality confusion.

5.2 Adaptive Remediation Trigger

If a student accumulates 2 or more consecutive errors on any concept, the adaptive engine intercepts the syllabus progression and generates a tailored reinforcement step before unlocking the next milestone.

7. Hackathon Judge Defence (Q&A)

Q1: Why Rust + Tauri v2 instead of Electron?
Tauri v2 gives us a 10-15MB binary and <35MB RAM footprint (vs 150MB+ bundle and 200MB+ RAM in Electron). It eliminates Node.js vulnerabilities, guarantees thread-safe execution, and runs smoothly on low-spec school computers.
Q2: How does the app operate 100% offline?
All 89 lesson curricula, the Three.js map engine, code editor, bilingual translation tables, Python subprocess bridge, and AST diagnostic heuristics are bundled locally on the device. Zero cloud dependencies.
Q3: How do you handle infinite loops or unsafe student code?
Python scripts run inside isolated child processes with hard 3000ms execution timeouts. If a student runs an infinite loop, the Rust backend terminates the child process and provides a clear pedagogical explanation of what happened.
Q4: How does the Three.js map maintain 60 FPS on integrated GPUs?
We use an OrthographicCamera with fixed frustum bounds, shared geometries, and an infinite ground plane that updates UV offsets rather than allocating new polygons. Total draw calls remain under 25 per frame.
Q5: How does the multi-stage code caching work?
Each stage code state is cached in an in-memory dictionary keyed by stage index. When students switch back and forth between completed stages, their working code is instantly restored without resetting progress.
Q6: What is the adaptive remediation mechanism?
The system maintains a real-time mistake ledger. When failure frequency on a specific concept hits the threshold (>= 2), the tutor interrupts the linear flow to serve a micro-targeted remediation module before clearing the ledger upon mastery.
Q7: How is the bilingual Malayalam translation synchronized?
We use a 1-to-1 localized translation map across all 89 lesson modules. Python keywords remain in standard English for syntax accuracy, while explanations, real-world analogies, hints, and quiz questions render natively in Malayalam.
Q8: How can judges or developers test the entire curriculum instantly?
We provide dedicated developer commands: devCompleteLesson() or keyboard shortcut Ctrl + Shift + L instantly completes the current lesson with 100% accuracy, while devCompleteAllLessons() unlocks all 9 modules at once.
Q9: What is your deployment model for school computer lab deployments?
Learner packages into self-contained installer executables (.msi / .dmg / .AppImage) requiring zero internet setup or cloud backend provision. School IT administrators can distribute the installer offline via USB drives or Windows Group Policy (GPO) across an entire computer lab in minutes.
